# lofi.room 서버 설계 (Supabase)

유튜브로 음악을 듣는 3D 리스닝 룸의 서버 쪽 설계입니다.
실제 테이블은 `supabase/migrations/20261008000000_listening_room.sql` 한 파일에 있습니다.
3D 화면 시안은 `prototype/room3d.html`입니다.

## 무엇을 저장하나

| 테이블 | 담는 것 |
|---|---|
| `lr_profiles` | 회원 한 명당 하나. 아이디(handle), 닉네임, 꾸민 캐릭터(`avatar` JSON) |
| `lr_rooms` | 회원 한 명당 방 하나. 가구·벽 장식·벽지·바닥 배치(`layout` JSON), 공개 범위, 대표 플레이리스트 |
| `lr_playlists` | 플레이리스트 이름과 순서 |
| `lr_playlist_tracks` | 플레이리스트 안의 곡. 유튜브 영상 ID 또는 유튜브 재생목록 ID와 제목 |
| `lr_photos` | 액자에 넣은 사진의 기록. 파일은 Storage `room-photos` 버킷의 `<회원id>/<사진id>.jpg` |
| `lr_follows` | 팔로우. 서로 팔로우하면 친구 |
| `lr_room_likes` | 방 좋아요 |
| `lr_guestbook` | 방명록 (300자) |

- 프로필을 만들면 방이 자동으로 하나 생깁니다.
- `layout` JSON은 3D 시안이 저장하는 모양 그대로입니다 (`floor[]`, `wall[]`, `surf`). 액자는 `p`에 `lr_photos.id`를 넣습니다.
- 모든 이름에 `lr_`를 붙여 이미 다른 앱이 쓰고 있는 Supabase 프로젝트에 같이 넣어도 이름이 겹치지 않게 했습니다.

## 누가 무엇을 볼 수 있나 (RLS)

방마다 공개 범위를 고릅니다: `public`(누구나), `friends`(서로 팔로우한 친구만), `private`(나만).

- 방, 플레이리스트, 곡, 사진(파일 포함)은 그 방의 공개 범위를 그대로 따릅니다.
- 꾸미기·플레이리스트 수정·사진 올리기는 주인만 할 수 있습니다.
- 사진은 자기 폴더(`<내 id>/`)에만 올릴 수 있습니다. 5MB 이하 JPEG/PNG/WebP만 받습니다.
- 좋아요와 방명록은 그 방을 볼 수 있는 로그인 회원만 남길 수 있습니다. 방명록은 쓴 사람이나 방 주인이 지울 수 있습니다.

로컬 Postgres에서 두 회원으로 확인한 결과:

| 상황 | 결과 |
|---|---|
| 친구 공개 방, 서로 팔로우 전 | 방·곡·사진 모두 안 보임 |
| 서로 팔로우한 뒤 | 모두 보임 |
| 남의 방 수정·남의 플레이리스트에 곡 추가·남의 폴더에 사진 올리기 | 모두 거부 |
| 로그인 안 한 방문자 | 공개 방만 보임 |

## 저장소에 없는 것

- **함께 듣기:** 지금 누가 방에 있는지, 같은 장면 재생, 채팅 말풍선은 저장하지 않고 Supabase Realtime 채널로 주고받습니다. 채널 이름은 `room:<방 id>`이고, presence에는 캐릭터 위치와 상태를, broadcast에는 재생·일시정지 시각과 반응을 담습니다.
- **유튜브 재생:** 실제 사이트에서는 유튜브 IFrame Player API로 TV 화면에 영상을 띄웁니다. 곡 제목은 유튜브 oEmbed로 서버(Edge Function)에서 받아 채울 수 있습니다.
